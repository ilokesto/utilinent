# 프록시 레지스트리 내부 구조

Proxy component는 base renderer, 알려진 HTML tag 전체, `Proxy` lookup을 조합해 만들어집니다. 읽기는 target의 기존 property를 먼저 확인하고, 다음으로 알려진 HTML tag, 마지막으로 요청된 category와 `base`를 `PluginManager`에서 확인합니다. 한번 resolve된 값은 target에 캐시되어 이후에는 바로 반환됩니다.

따라서 `Show.div`는 즉시 사용할 수 있고, `Show.Link`는 `PluginManager.register({ show: { Link } })` 이후 사용할 수 있습니다.

## 지연 생성되는 tag wrapper

Tag wrapper는 proxy가 만들어지는 시점이 아니라 최초 접근 시 생성됩니다. `Show.div`를 처음 읽으면 wrapper를 만들어 캐시하고, 이후의 모든 읽기는 같은 인스턴스를 반환합니다.

패키지를 가져오면 다섯 개의 polymorphic proxy(`Show`, `For`, `Mount`, `Repeat`, `Switch`)가 평가됩니다. 이전에는 모듈 평가 시점에 각 proxy가 알려진 모든 tag의 wrapper를 미리 만들었습니다(85 tag × 5 proxy = 425개 `forwardRef` wrapper). 지금은 tag variant를 처음 읽기 전까지 아무 wrapper도 만들지 않습니다. 이 수치는 패키지의 counting factory 테스트로 측정한 생성 횟수이며, wrapper당 heap 절감량은 측정하지 않았습니다.

Reflection 동작은 이전과 같은 형태를 유지합니다.

- `"span" in Show`는 wrapper를 만들지 않고 `true`를 반환합니다.
- `Object.keys(Show)`와 `for...in`은 여전히 모든 tag를 나열합니다. 나열은 각 property descriptor를 읽기 때문에 아직 만들지 않은 wrapper를 실제로 생성하므로, 사용하지 않는 tag의 할당을 피하려면 직접 접근(`Show.span`)을 사용하세요.
- `Object.getOwnPropertyDescriptor(Show, "div")`도 wrapper를 생성하며, 그 `value`는 항상 property 접근 결과와 일치합니다.

## 캐싱

Plugin-backed property가 resolve되면 utilinent는 specialized component를 현재 proxy target에 저장합니다. Property를 읽는 rendering code보다 먼저 plugin을 등록하세요. 한번 캐시된 wrapper는 plugin이 unregister된 이후에도 proxy에 남으며, registry 변경을 반영하려면 새 proxy를 만들어야 합니다.
