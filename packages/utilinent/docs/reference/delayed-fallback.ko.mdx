# DelayedFallback

`DelayedFallback`은 [usePendingDelay](./use-pending-delay)를 사용하는 얇은 컴포넌트입니다. 훅이 `true`를 반환하는 동안 `fallback`을, 그 외에는 `children`을 렌더링합니다.

아직 출시되지 않은 API이며 `@ilokesto/utilinent` 1.2.1에는 포함되지 않습니다.

```tsx lineNumbers
import { DelayedFallback } from '@ilokesto/utilinent';

function Results({ pending, result }: { pending: boolean; result: string }) {
  return (
    <DelayedFallback.section
      pending={pending}
      delay={200}
      minDuration={300}
      aria-busy={pending}
      aria-label="검색 결과"
      fallback={<span role="status">결과를 갱신하는 중…</span>}
    >
      <p>{result}</p>
    </DelayedFallback.section>
  );
}
```

200 ms보다 짧은 요청에서는 기존 결과가 그대로 보입니다. 더 오래 걸리는 요청은 결과를 상태 알림으로 교체하고, 표시 시작부터 최소 300 ms 동안 유지합니다. 완료 후 남은 최소 노출 시간도 포함합니다.

## Props

| Prop | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `pending` | `boolean` | 필수 | 현재 작업이 대기 중인지 여부. |
| `delay` | `number` | `200` | `fallback` 표시 전 지연 시간(ms). |
| `minDuration` | `number` | `300` | 표시 시작부터 계산하는 최소 노출 시간(ms). |
| `fallback` | `ReactNode` | `null` | 지연된 대기 UI가 표시되는 동안의 콘텐츠. |
| `children` | `ReactNode` | — | 표시 전과 최소 노출 유지가 끝난 뒤의 콘텐츠. |

시간 계산, 옵션 변경, 0인 시간, SSR, 정리 규칙은 `usePendingDelay`와 같습니다.

## 콘텐츠와 로딩 UI 구성

초기 지연 동안에는 자식이 마운트된 상태로 남습니다. 대체 UI가 나타나면 언마운트되고, `pending`이 이미 false여도 최소 노출 유지가 끝난 뒤 다시 마운트됩니다. 로컬 상태를 보존해야 하는 콘텐츠는 이 교체 분기 안에 넣지 마세요.

결과를 계속 마운트하려면 훅 참조 페이지처럼 별도의 상태 영역과 조합하세요. 지연된 표시만 필요하면 자식을 생략합니다.

```tsx lineNumbers
<DelayedFallback pending={pending} fallback={<span role="status">불러오는 중…</span>} />
```

기본 컴포넌트는 DOM 래퍼를 추가하지 않습니다. `DelayedFallback.div`, `.section` 등의 프록시 태그는 래퍼를 계속 마운트하고 호스트 props와 ref를 전달하며, 시간 관련 props를 DOM으로 전달하지 않습니다. 등록한 대상은 `delayedFallback` 카테고리를 사용하고 기존 `base` 레지스트리를 대체 경로로 지원합니다.

접근 가능한 로딩 문구와 상태 의미는 직접 제공하세요. `aria-busy={pending}`에는 지연된 표시 상태가 아니라 실제 작업 상태를 사용합니다. 컴포넌트는 ARIA 속성을 자동 추가하거나, 동작을 비활성화하거나, Suspense를 처리하지 않습니다.
