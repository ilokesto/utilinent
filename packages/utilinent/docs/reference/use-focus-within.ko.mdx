# useFocusWithin

`useFocusWithin`은 참조가 안정적인 callback `ref`와 `isFocusWithin` boolean을
반환합니다. 그룹 내부의 포커스에 따라 렌더링이나 애플리케이션 동작을 변경할 때
사용하세요. 스타일만 변경한다면 CSS `:focus-within`을 우선 사용하세요.

```tsx lineNumbers
import { useFocusWithin } from '@ilokesto/utilinent/hooks';

function SearchGroup() {
  const { ref, isFocusWithin } = useFocusWithin();
  return (
    <div ref={ref}>
      <label>
        검색
        <input type="search" aria-describedby="search-help" />
      </label>
      <button type="button">검색</button>
      <p id="search-help" hidden={!isFocusWithin}>
        검색어를 입력한 다음 검색 버튼을 선택하세요.
      </p>
    </div>
  );
}
```

## API

```ts
function useFocusWithin(): {
  ref: (node: HTMLElement | null) => void;
  isFocusWithin: boolean;
};
```

`ref`는 하나의 HTML 요소에 연결합니다. 요소 자신이나 DOM 자손에 포커스가 있으면
`true`입니다. 키보드, 포인터, 프로그램으로 이동한 포커스 모두 같은 상태로
반영합니다. 대상의 DOM 하위 트리 밖에 렌더링된 portal 콘텐츠는 내부로 보지 않습니다.

훅은 `focusin`과 `focusout`을 구독합니다. `focusout`의 `relatedTarget`이 대상
내부에 남아 있으면 `true`를 유지하므로 자손 사이를 이동할 때 잠시 이탈 상태가
되지 않습니다. 포커스가 외부로 이동하거나 `relatedTarget`이 `null`인 blur가
발생하면 `false`가 됩니다.

## 연결과 수명주기

- 서버 렌더와 첫 클라이언트 렌더는 모두 `false`를 반환하여 hydration 결과를
  일치시킵니다. 연결 후에는 `ownerDocument.activeElement`를 확인하므로 연결이나
  hydration 이전에 이미 포커스를 받은 자손도 반영합니다.
- 대상이 나중에 마운트되거나 다른 요소로 교체되어도 현재 대상에 맞춰 구독합니다.
  교체 시에는 새 요소의 포커스 상태를 반영합니다.
- ref가 `null`이 되면 상태는 `false`로 초기화됩니다. 교체, 연결 해제, 언마운트
  시 이전 listener를 제거하며 Strict Mode 재실행에서도 정리합니다.
- 일반적인 재렌더에서는 callback ref를 유지하고 listener를 다시 등록하지
  않습니다. 내부 포커스 이동으로 boolean이 바뀌지 않으면 상태를 갱신하지 않습니다.

## 스타일에는 CSS 우선 사용

```css
.search-group:focus-within {
  outline: 2px solid currentColor;
  outline-offset: 4px;
}
```

이 훅은 포커스를 관찰만 합니다. 포커스 이동이나 trap, Tab 순서 변경,
modal이나 overlay 수명 관리, ARIA 속성 자동 추가는 하지 않습니다. 기본
포커스 가능 컨트롤과 눈에 보이는 포커스 표시를 유지하고 접근 가능한 이름과
관계는 호출하는 쪽에서 지정하세요.
