# useInfiniteSentinel

목록 끝의 측정 가능한 HTML 요소에 콜백 `ref`를 연결합니다. 최초 한 번만 실행하는 지연 로딩과 달리, sentinel이 계속 보이는 동안 다음 페이지를 요청할 수 있습니다.

```tsx lineNumbers
import { useInfiniteSentinel } from '@ilokesto/utilinent/hooks';

function PageSentinel({ fetchNextPage, hasNextPage, isFetchingNextPage }) {
  const { ref, isLoading, isError, retry } = useInfiniteSentinel({
    onLoadMore: fetchNextPage,
    hasMore: hasNextPage,
    busy: isFetchingNextPage,
    rootMargin: '200px',
  });

  return (
    <div ref={ref} style={{ minHeight: 1 }}>
      {isLoading ? '불러오는 중...' : null}
      {isError ? <button type="button" onClick={retry}>다시 시도</button> : null}
    </div>
  );
}
```

## 옵션

| 옵션 | 타입 | 기본값 / 책임 |
| --- | --- | --- |
| `onLoadMore` | `() => void \| Promise<unknown>` | 필수. 소비자가 소유한 작업을 시작합니다. 완료까지 내부 잠금을 유지하려면 해당 promise를 반환합니다. |
| `hasMore` | `boolean` | 필수. 다음 페이지가 없으면 `false`로 설정합니다. |
| `busy` | `boolean` | `false`. 소비자의 로딩 상태입니다. 커밋된 `true` → `false` 전환은 보이는 sentinel을 다시 활성화합니다. |
| `disabled` | `boolean` | `false`. 자동 로딩과 수동 재시도를 중단합니다. |
| `onError` | `(error: unknown) => void` | 선택 사항. 동기 예외나 promise 거부를 알립니다. 이 콜백 자체는 예외를 던지지 않아야 합니다. |
| `root` | `Element \| null` | `null` (뷰포트). 중첩 스크롤에서는 스크롤 컨테이너를 전달합니다. |
| `rootMargin` | `string` | `"0%"`. 양수 여백으로 화면에 들어오기 전에 미리 불러올 수 있습니다. |
| `threshold` | `number \| number[]` | `0`. 값 기준으로 정규화하며 같은 옵션은 네이티브 observer를 공유합니다. |

## 반환값

| 필드 | 의미 |
| --- | --- |
| `ref` | `HTMLElement \| null`을 받는 안정적인 콜백 ref입니다. |
| `isIntersecting` | 현재 대상이 교차 및 threshold 조건을 만족하는지 나타냅니다. 초기값은 `false`입니다. |
| `isLoading` | 제어형 `busy` 또는 내부 콜백 결과의 처리 중 상태입니다. |
| `isError` | 오류 값과 독립적인 boolean 실패 상태입니다. 초기값은 `false`이며 실패하면 `true`, 조건을 만족하는 새 시도가 시작되면 `false`가 됩니다. |
| `error` | `undefined`를 포함한 원래 `unknown` 실패 값입니다. 조건을 만족하는 새 시도가 시작되면 `undefined`로 초기화합니다. 실패 여부는 이 값의 참/거짓 변환이 아닌 `isError`로 판별하세요. |
| `retry()` | 뷰포트 밖이나 IntersectionObserver 미지원 환경에서도 사용할 수 있는 안정적인 수동 시도 함수입니다. `busy`, `disabled`, `hasMore`, 마운트된 대상 및 내부 잠금은 여전히 적용합니다. |

## 소유권과 반복 로딩

페이지 데이터, 캐시, 취소, `busy`, `hasMore`는 소비자가 소유합니다. 훅은 관찰, 중복 호출 방지 잠금, 실패 상태를 소유합니다. 소비자가 전달한 promise를 취소하지 않습니다.

조건을 만족하는 진입마다 한 번 요청합니다. 계속 교차 중인 레코드를 받아도 다시 요청하지 않습니다. 커밋된 `busy: true` → `false` 전환은 이탈 없이도 다음 요청을 활성화합니다. `disabled`를 해제하거나 `hasMore`를 다시 `true`로 바꾸어도 재활성화합니다. 보이지 않거나 busy, disabled, 실패, 마지막 페이지 상태이면 자동 요청하지 않습니다. promise 처리 중 재활성화되면 완료까지 기다리며 여러 신호는 한 번의 요청 기회로 합쳐집니다.

Promise 이행만으로는 **다음 페이지를 요청하지 않습니다**. 즉시 완료되거나 동기적인 콜백의 무한 반복을 방지하기 위한 계약입니다. 스크롤 영역이 채워질 때까지 연속 로딩하려면 데이터 로더의 커밋된 `busy` 상태 전환을 전달하세요. 동기 콜백으로 별도 비동기 작업을 시작한다면 작업 중 `busy`를 유지해야 합니다. 그렇지 않으면 훅은 콜백 호출 턴만 잠급니다.

콜백 참조만 변경하면 재활성화하거나 관찰을 다시 시작하지 않습니다. 다음 시도와 오류 알림은 최신 커밋된 콜백을 사용합니다. 대상을 교체하면 가시성을 새로 관찰하기 전에는 로딩하지 않습니다.

## 실패와 정리

동기 예외나 반환된 promise 거부는 `isError`를 `true`로 설정하고 원래 값을 `error`에 보존하며, 같은 값으로 `onError`를 호출하고 자동 요청을 중단합니다. `undefined`, `null`, `""`, `false`, `0`도 포함하므로 `error`만으로는 실패 여부를 판별할 수 없습니다.

같은 교차 상태의 레코드나 `busy` 전환만으로는 재시도하지 않습니다. `retry()`를 호출하거나 sentinel이 이탈 후 다시 진입하면 재시도합니다. 대상 또는 observer 옵션 변경으로 새 관찰이 시작되어도 새 진입을 허용합니다. 조건을 만족하는 새 시도가 시작될 때만 `isError`는 `false`, `error`는 `undefined`로 초기화됩니다. 뷰포트 이탈, 관찰 옵션 변경, 차단된 재시도만으로는 초기화하지 않으며 성공 후에도 초기화된 상태를 유지합니다. 비동기 실패를 감지하려면 promise를 반환해야 합니다. 오류를 자체 처리하는 콜백은 재시도 정책도 직접 관리해야 합니다.

Unmount 시 관찰을 해제하며 늦게 끝난 작업은 `onError`나 다음 로딩을 실행하지 않습니다. StrictMode의 effect 재실행만으로 로딩을 시작하지 않습니다. 서버와 IntersectionObserver 미지원 브라우저에서는 자동 로딩하지 않습니다. 계속 로딩할 수 있어야 한다면 수동 재시도 버튼을 제공하세요.

훅은 요소의 크기를 설정하지 않습니다. 측정 가능한 크기를 직접 지정하거나 기본 최소 크기를 제공하는 [LoadMore](./load-more)를 사용하세요.
