# usePendingDelay

`usePendingDelay`는 대기 UI를 표시할지 나타내는 불리언을 반환합니다. 지연 시간 전에 완료된 요청은 표시하지 않고, 한 번 표시한 UI는 최소 노출 시간 동안 유지합니다.

아직 출시되지 않은 API이며 `@ilokesto/utilinent` 1.2.1에는 포함되지 않습니다.

```tsx lineNumbers
import { usePendingDelay } from '@ilokesto/utilinent/hooks';

function SearchResults({ pending, results }: { pending: boolean; results: string[] }) {
  const isVisible = usePendingDelay(pending, { delay: 200, minDuration: 300 });

  return (
    <section aria-busy={pending} aria-label="검색 결과">
      <div role="status">{isVisible ? '결과를 갱신하는 중…' : null}</div>
      <ul>{results.map((result) => <li key={result}>{result}</li>)}</ul>
    </section>
  );
}
```

`pending`이 200 ms 전에 끝나면 상태 영역은 비어 있습니다. 더 오래 걸리면 표시 시점부터 최소 300 ms 동안 상태를 표시합니다. 이 구성은 결과를 마운트한 상태로 유지하며, 실제 작업 여부는 `aria-busy={pending}`으로 전달합니다. 표시 UI는 작업 완료 후에도 잠시 남을 수 있습니다.

## 시그니처

```ts
usePendingDelay(pending: boolean, options?: UsePendingDelayOptions): boolean
```

| 옵션 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `delay` | `number` | `200` | 대기 상태가 연속으로 유지되어야 하는 표시 전 지연 시간(ms). |
| `minDuration` | `number` | `300` | 요청 시작이나 완료가 아닌 실제 표시 시작부터 계산하는 최소 노출 시간(ms). |

0은 해당 단계의 대기를 생략합니다. 음수와 유한하지 않은 값은 0으로 처리하고, 2,147,483,647 ms를 초과하는 유한 값은 타이머 한도인 이 값으로 제한합니다.

## 시간 계산과 갱신

- 처음부터 대기 중인 작업에도 이후 요청과 같은 지연 시간을 적용합니다.
- 표시 전에 완료되면 타이머를 취소합니다. 다음 요청에는 새 지연 시간을 적용합니다.
- 표시 후 완료되면 `minDuration` 중 남은 시간만 유지합니다. 이미 최소 시간을 채운 긴 요청은 완료 즉시 숨깁니다.
- 최소 노출 유지 중 다시 대기 상태가 되면 숨김을 취소합니다. 표시가 끊기지 않으며, 최소 노출 시간을 새로 시작하지 않고 원래 표시 시점을 유지합니다.
- 표시 대기 중 `delay`를 바꾸면 원래 대기 시작을 기준으로 기한을 다시 계산합니다. 이미 지난 시간보다 짧게 바꾸면 즉시 표시하고, 늘리면 기한이 연장됩니다. 표시 후의 변경은 UI를 숨기지 않습니다.
- `minDuration` 변경도 원래 표시 시점을 기준으로 합니다. 유지 중 값을 늘리면 기한을 연장하고, 경과 시간보다 줄이면 즉시 숨깁니다. 아직 작업 중이면 완료 시 최신 값을 적용합니다.
- 표시 또는 숨김 기한에만 타이머를 사용합니다. 유휴 상태와 표시된 채로 작업 중인 상태에는 타이머가 없습니다. 언마운트와 Strict Mode effect 정리 시 예약된 작업을 취소합니다.

타이머는 React가 커밋한 갱신을 따릅니다. 서버 렌더링과 첫 hydration 렌더링에서는 지연 시간이 0이어도 `false`를 반환합니다. 클라이언트 마운트부터 시간을 계산하며, 지연 시간이 0이면 클라이언트 layout effect에서 동기화합니다.

동작 비활성화나 실제 작업 상태 알림에는 원래 `pending`을 사용하세요. 반환값은 표시 정책일 뿐, 요청을 시작·취소·대기하거나 suspend하지 않습니다.

콘텐츠를 마운트한 상태로 유지하지 않고 분기를 교체하려면 [DelayedFallback](./delayed-fallback)을 사용하세요.
