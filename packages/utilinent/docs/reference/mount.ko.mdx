# Mount

`Mount`는 직접 전달한 React node를 즉시 렌더링합니다. 비동기 작업은 Promise를 반환하는 factory로 전달해야 합니다. 직접 `Promise` 및 `PromiseLike` child는 React 18과 React 19 type 모두에서 지원하지 않습니다.

```tsx lineNumbers
import { Mount } from '@ilokesto/utilinent';

<Mount fallback={<p>Preparing preview...</p>}>
  {async () => <Preview data={await loadPreview()} />}
</Mount>
```

## 프로퍼티

| Prop | Type | 설명 |
| --- | --- | --- |
| `children` | `MountNode \| ((signal: AbortSignal) => ReactNode \| Promise<ReactNode>)` | 직접 node 또는 동기/비동기 node factory입니다. `MountNode`는 `PromiseLike` 값을 제외한 `ReactNode`입니다. Factory는 signal을 무시할 수 있으며 인자 없는 factory도 그대로 허용됩니다. |
| `fallback` | `ReactNode` | Factory의 초기 출력이며 Promise가 pending인 동안과 error 이후에 유지됩니다. 기본값은 `null`입니다. |
| `onError` | `(error: unknown) => void` | 현재 factory가 throw 또는 reject하면 원래 error를 받습니다. |

## Factory로만 비동기 작업 전달하기

비동기 작업은 child factory 안에서 호출하세요.

```tsx lineNumbers
<Mount fallback={<Spinner />} onError={reportError}>
  {() => loadPreview().then((preview) => <Preview data={preview} />)}
</Mount>
```

Render 중에 작업을 시작하고 그 Promise를 `children`으로 직접 전달하지 마세요. React 19가 promise를 `ReactNode`에 포함하더라도 직접 `Promise<ReactElement>`, `Promise<string>`, 기타 `PromiseLike` child는 public type과 runtime contract 모두에서 의도적으로 지원하지 않습니다.

## 실행 시점, 대체 UI, 오류

- 직접 node는 초기 출력이며 `fallback`을 사용하지 않습니다.
- Function child는 `fallback`으로 시작합니다. `Mount`는 commit 이후 layout effect에서 function을 호출합니다.
- 동기 결과는 해당 effect에서 fallback을 교체하며, 일반적으로 browser paint 전에 반영됩니다.
- Promise 결과가 pending인 동안에는 fallback이 계속 보입니다.
- 동기 throw 또는 현재 Promise의 rejection은 fallback을 유지하고, 기존 console error를 기록하며, 실패한 invocation에 대해 `onError`를 한 번 호출합니다.
- React Strict Mode는 development에서 effect를 다시 실행할 수 있으므로 factory는 여러 번 호출되어도 안전해야 합니다.

## 태그 형태

```tsx lineNumbers
<Mount.div fallback={<Spinner />} className="preview">
  {() => <Preview />}
</Mount.div>
```

## 경합 안전성

`children`이 바뀌면 더 최신 call이 시작됩니다. 이전 call의 fulfillment 또는 rejection은 무시되므로 현재 출력을 교체할 수 없고 `onError`도 호출하지 않습니다. Unmount 이후 settlement도 같은 방식으로 무시합니다. Pending 비동기 작업을 직접 node로 교체하면 해당 node를 즉시 표시합니다.

## AbortSignal로 취소하기

Factory는 현재 attempt의 `AbortSignal`과 함께 호출됩니다. `Mount`는 attempt가 대체될 때 이 signal을 abort합니다. `children` 또는 `onError`의 identity가 바뀔 때, component가 unmount될 때, development에서 Strict Mode가 첫 effect pass를 버릴 때입니다.

```tsx lineNumbers
<Mount fallback={<Spinner />} onError={reportError}>
  {(signal) =>
    fetch(`/api/preview/${id}`, { signal })
      .then((res) => res.json())
      .then((preview) => <Preview data={preview} />)
  }
</Mount>
```

- 인자 없는 factory는 그대로 계속 동작합니다. JavaScript가 남는 인자를 무시하며, 위의 stale-result guard는 늦은 settlement를 계속 무시합니다.
- Signal을 읽지 않는 작업은 `Mount`가 취소하지 않습니다. UI에 영향을 주지 않게 될 뿐입니다.
- `Mount`가 이미 abort한 attempt에서 도착한 `AbortError` rejection은 조용히 버립니다. `onError`도, console error도, 추가 작업도 없습니다.
- 현재 진행 중인 attempt에서 발생한 `AbortError`는 다른 failure와 동일하게 보고됩니다.

## Function identity와 재실행

`Mount`는 `children` 또는 `onError` function의 identity가 바뀔 때 factory를 다시 실행합니다. Closure가 capture한 값이 바뀔 때가 아니라 reference가 바뀔 때입니다. Inline factory나 inline `onError`는 부모가 render할 때마다 새 identity가 되므로, 관련 없는 re-render마다 작업이 다시 시작됩니다.

```tsx lineNumbers
export function PreviewPanel({ id }: { id: string }) {
  const [ticks, setTicks] = useState(0);
  return (
    <div>
      {/* Render마다 새 function identity: 부모가 re-render될 때마다 request가 재시작됩니다. */}
      <Mount fallback={<Spinner />}>
        {() => fetchPreview(id).then((preview) => <Preview data={preview} />)}
      </Mount>
      <button type="button" onClick={() => setTicks((count) => count + 1)}>
        관련 없는 state {ticks}
      </button>
    </div>
  );
}
```

무조건 모두 memoize하지 말고 실제 입력을 dependency list에 넣으세요. 안정적인 factory는 관련 없는 re-render를 견디고, 입력이 바뀌는 것이 더 최신 request를 시작하는 의도된 방법입니다.

```tsx lineNumbers
export function PreviewPanel({ id }: { id: string }) {
  const [ticks, setTicks] = useState(0);
  const loadPreview = useCallback(
    () => fetchPreview(id).then((preview) => <Preview data={preview} />),
    [id],
  );
  return (
    <div>
      <Mount fallback={<Spinner />} onError={reportError}>{loadPreview}</Mount>
      <button type="button" onClick={() => setTicks((count) => count + 1)}>
        관련 없는 state {ticks}
      </button>
    </div>
  );
}
```

이 version에서는 button을 클릭해도 `loadPreview`가 다시 실행되지 않고, `id`가 바뀌면 새 attempt가 시작되며 이전 signal이 abort됩니다. Reference 변경이 의도된 update 경로입니다. 입력이 실제로 바뀌었을 때만 새 function을 만들고, 그렇지 않을 때는 같은 function을 유지하세요. `onError`의 identity 변경도 현재 attempt를 다시 시작하므로, inline으로 전달한다면 같은 방식으로 안정적으로 유지하세요.
