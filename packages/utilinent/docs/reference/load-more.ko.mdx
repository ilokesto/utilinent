# LoadMore

`LoadMore`는 목록 끝에 sentinel을 렌더링하고 로딩을 [useInfiniteSentinel](./use-infinite-sentinel)에 위임합니다. 페이지 데이터, 캐시, 가상화는 소유하지 않습니다.

```tsx lineNumbers
import { LoadMore } from '@ilokesto/utilinent';

<LoadMore
  onLoadMore={fetchNextPage}
  hasMore={hasNextPage}
  busy={isFetchingNextPage}
  rootMargin="200px"
>
  {({ isLoading, error, retry }) => (
    <>
      {isLoading ? <span role="status">불러오는 중...</span> : null}
      {error ? <button type="button" onClick={retry}>다시 시도</button> : null}
    </>
  )}
</LoadMore>
```

## Props와 children

모든 [훅 옵션](./use-infinite-sentinel)을 받습니다. `onLoadMore`, `hasMore`는 필수이고 `busy`, `disabled`, `onError`, `root`, `rootMargin`, `threshold`는 선택 사항입니다.

`children`은 React 노드 또는 `{ isIntersecting, isLoading, error, retry }`를 받는 렌더 함수를 받습니다. 보이지 않거나 비활성화되거나 마지막 페이지에 도달해도 항상 렌더링합니다. 로딩 알림, 오류 메시지, 수동 컨트롤을 직접 제공하세요. fallback, 상태 알림, 버튼 동작은 자동으로 추가하지 않습니다.

호출자가 `busy`와 `hasMore`를 제어합니다. sentinel이 계속 보이는 상태에서 `busy: true` → `false`로 바뀌면 다음 페이지를 요청합니다. 반환한 promise는 중복 호출을 막지만 완료 자체가 다음 페이지를 요청하지는 않습니다. 예외 또는 거부 후에는 명시적인 재시도나 새 진입 전까지 자동 로딩을 중단합니다. 전체 실패 및 정리 정책은 훅 문서를 참고하세요.

## 측정 가능한 호스트와 프록시 태그

기본 호스트는 `div`이며 `minHeight: "1px"`, `minWidth: "1px"`, `display: "block"`을 설정합니다. 내용이 없거나 로딩이 끝나도 이 크기를 유지합니다. 소비자의 `style`로 기본값을 덮어쓸 수 있습니다. 자동 관찰이 필요하다면 `display: none`, `display: contents` 또는 크기가 없는 박스를 피하세요.

```tsx lineNumbers
<ul>
  {items.map((item) => <li key={item.id}>{item.name}</li>)}
  <LoadMore.li
    onLoadMore={fetchNextPage}
    hasMore={hasNextPage}
    busy={isFetchingNextPage}
    aria-label="항목 더 불러오기"
  />
</ul>
```

`LoadMore.li`, `LoadMore.section`, `LoadMore.button` 같은 HTML 변형은 호스트 props와 구체적인 요소 ref 타입을 전달합니다. 기본 `LoadMore`는 `HTMLDivElement` ref를 전달합니다. 버튼 태그에 클릭 핸들러가 자동 연결되지는 않습니다. 수동 버튼은 렌더 함수의 `retry`를 사용하세요.

프록시 등록은 `loadMore` 카테고리와 일반적인 `base` fallback을 사용합니다. 커스텀 대상은 측정 가능한 HTML 요소로 ref를 전달하고 `style`과 나머지 호스트 props도 전달해야 합니다. `disabled`, `onError`를 포함한 훅 옵션은 소비되며 네이티브 호스트 속성이나 이벤트로 전달되지 않습니다.

서버와 IntersectionObserver 미지원 환경에서도 호스트와 children은 렌더링하지만 자동 로딩은 비활성화됩니다. 필요하면 `retry`를 수동 컨트롤로 제공하세요. Unmount는 소비자의 작업을 취소하지 않고 observer만 해제합니다.
