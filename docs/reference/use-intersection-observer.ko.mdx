# useIntersectionObserver

`useIntersectionObserver`는 `Observer`가 내부적으로 사용하는 hook입니다. Intersection state 주변에 custom rendering이나 side effect가 필요할 때 직접 사용하세요.

```tsx lineNumbers
import { useIntersectionObserver } from '@ilokesto/utilinent/hooks';

function AnalyticsSection() {
  const { ref, isIntersecting, entry } = useIntersectionObserver({
    threshold: 0.5,
    freezeOnceVisible: true,
    onIntersect: () => console.log('seen'),
  });

  return <section ref={ref}>{isIntersecting ? 'Visible' : 'Hidden'}</section>;
}
```

## Options

| Option | 설명 |
| --- | --- |
| `threshold` | number 또는 number array입니다. 기본값은 `0`입니다. |
| `root` | optional root element입니다. 기본값은 viewport입니다. |
| `rootMargin` | root 주변 margin입니다. 기본값은 `"0%"`입니다. |
| `freezeOnceVisible` | 처음 visible해진 뒤 해당 대상의 observing을 멈춥니다. |
| `initialIsIntersecting` | observing 전 initial state입니다. |
| `onIntersect` | initial observation 이후 entering intersection 시 호출됩니다. |
| `onChange` | **Deprecated** `onIntersect`의 alias입니다. |

## 반환값

`ref`는 callback ref입니다. 관찰할 element에 연결하세요. `isIntersecting`은 현재 boolean state입니다. `entry`는 사용 가능한 최신 `IntersectionObserverEntry`입니다. 전달되는 모든 record는 boolean이 그대로여도 `entry`를 갱신하므로 ratio·좌표 소비자는 계속 새 값을 받습니다.

## Threshold 정규화

threshold는 배열 identity가 아니라 값 집합으로 비교합니다. `0.5`, `[0.5]`, `[0.5, 0]`, `[0, 0.5, 0.5]`는 모두 동등합니다. 값을 중복 제거하고 정렬하며, 이는 native observer가 순서와 중복을 다루는 방식과 같습니다. 빈 배열은 `[0]`으로 취급합니다.

이 덕분에 hook 소유 컴포넌트가 매 렌더마다 새로 만드는 inline 배열로도 observer가 다시 생성되지 않고, 실제 값이 바뀔 때만 관찰이 교체됩니다. 부모 JSX에 적은 `threshold={[0, 0.5]}`는 자식 로컬 재렌더로 새로 생성되지 않으며, 이 보호가 대상으로 하는 것은 hook을 호출하는 컴포넌트가 렌더마다 배열을 직접 만드는 경우입니다.

## Native observer 공유

같은 root element identity, `rootMargin`, 정규화된 threshold 값을 가진 구독은 하나의 native `IntersectionObserver`를 공유합니다. record는 대상 element에 따라 각 hook 인스턴스의 handler로만 전달됩니다.

한 대상을 freeze하거나 구독을 해제해도 해당 대상만 해제되며(`unobserve`) 공유 observer의 다른 대상은 계속 관찰됩니다. 마지막 구독이 해제되면 native observer가 disconnect되고 registry 항목이 제거되어, 이후에는 관찰되던 element를 붙잡는 참조가 남지 않습니다.

## freezeOnceVisible 의미

freeze는 관찰 대상에 한정됩니다. element가 제거되거나 새 node로 교체되거나 다시 연결되면 frozen 상태가 초기화되고 새 대상을 처음부터 다시 관찰합니다. freeze된 이후 `freezeOnceVisible`을 끄면 관찰도 재개됩니다. `onIntersect`는 현재 대상의 수명 동안 각 `false → true` 전환마다 호출되며, 새 대상의 첫 intersecting record도 그러한 전환으로 취급됩니다.
