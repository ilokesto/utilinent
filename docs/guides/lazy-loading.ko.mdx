# 지연 로딩

이미 content가 있고 visible할 때만 렌더링하고 싶다면 `Observer`를 사용하세요. Visibility가 data loading을 시작해야 한다면 `Slacker`를 사용하세요.

```tsx lineNumbers
<Observer rootMargin="200px" fallback={<ChartPlaceholder />} triggerOnce>
  <HeavyChart />
</Observer>
```

```tsx lineNumbers
<Slacker loader={loadChartData} loadingFallback={<ChartPlaceholder />}>
  {(data) => <HeavyChart data={data} />}
</Slacker>
```

## 실전 지침

- User가 content에 도달하기 전에 preload하려면 `rootMargin`을 설정하세요.
- 처음 visible된 뒤 계속 mount되어야 하는 content는 `triggerOnce`를 사용하세요.
- Component 안에서 loader를 선언한다면 `useCallback`으로 안정적으로 유지하세요.
- Layout shift를 줄이려면 fallback에 실제 높이를 주세요.

## 지연 로딩은 virtualization이나 cache 회수가 아닙니다

`Slacker`는 load *시작 시점*을 늦출 뿐입니다. Load가 성공하면 data는 component state에 유지되고 observer는 `triggerOnce`이므로, section이 viewport를 벗어나도 content가 unmount되지 않고 data가 해제되지 않습니다. `Slacker`를 cache 회수 도구로 사용하지 마세요.

`Observer`와 `Slacker`는 긴 list를 windowing하지도 않습니다. `For`는 받은 array의 모든 item을 render하므로 10,000개 항목은 10,000개 row를 mount합니다. 지연 로딩이 답하는 질문은 "이 section이 언제 작업을 시작할까?"이고, pagination과 virtualization이 답하는 질문은 "한 번에 몇 개 row가 존재할까?"입니다.

## Lazy list가 실제로 mount하는 양 제한하기

실제로 mount되는 row 수는 자신의 pagination state로 제한하고, list가 load를 시작하는 시점만 `Slacker`로 늦추세요.

```tsx lineNumbers
import { useState } from 'react';
import { For, Slacker } from '@ilokesto/utilinent';

const PAGE_SIZE = 25;

function PagedProductList({ items }: { items: Array<{ id: number }> }) {
  const [visibleCount, setVisibleCount] = useState(PAGE_SIZE);
  const visibleItems = items.slice(0, visibleCount);
  return (
    <div>
      <For.ul each={visibleItems}>
        {(item) => <li key={item.id}>{item.name}</li>}
      </For.ul>
      {visibleCount < items.length ? (
        <button type="button" onClick={() => setVisibleCount((count) => count + PAGE_SIZE)}>
          더 보기
        </button>
      ) : null}
    </div>
  );
}

<Slacker loader={(signal) => fetchProducts(signal)} loadingFallback={<ProductSkeleton />}>
  {(products) => <PagedProductList items={products} />}
</Slacker>
```

이 방식으로 500개 product를 load해도 처음에 mount되는 row는 `PAGE_SIZE`개뿐이고, 클릭할 때마다 한 page씩 늘어납니다. 각 row는 item identity 기반의 안정적인 `key`를 유지하고 semantic `<ul>` markup 안에 있습니다. Pagination은 mount되는 DOM만 제한하며 data 준비를 공짜로 만들지는 않습니다. 500개 항목을 fetch, parse, 보관하는 비용은 그대로입니다.

한 번에 수천 개 row를 보여야 한다면 이 pattern을 전용 virtualization library와 함께 사용하세요. Utilinent는 virtualization engine을 포함하지 않으며, 여기서 특정 memory 절감률을 주장하지 않습니다.
